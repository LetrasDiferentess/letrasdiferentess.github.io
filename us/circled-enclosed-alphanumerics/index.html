Circled and Enclosed Unicode Alphanumerics: Mapping, Normalization and Compatibility

A comprehensive reference to circled digits and Latin letters, parenthesized forms, negative and double circles, CJK enclosed symbols, NFKC folding and font fallback.

Technical referenceUnicode baseline: 18.0.0Updated 25 October 2026

Enclosed symbols are characters, not CSS borders

Unicode includes many characters that visually enclose a letter, number or abbreviation in a circle, parenthesis, square or other frame. ① is the single encoded character U+2460 CIRCLED DIGIT ONE, not the character 1 with an HTML border attached. Likewise, Ⓐ is U+24B6 CIRCLED LATIN CAPITAL LETTER A. The enclosure is part of the code point's character identity, though the glyph design itself still depends on a font.

Many enclosed forms entered Unicode for compatibility with historical East Asian character encodings and common typesetting conventions such as numbered bullets, circled list references and broadcast labels. Their appearance can be useful for copyable plain-text lists, but these symbols are not a universal way to encircle arbitrary text. A generic string like "203" does not necessarily have a single corresponding encoded circled symbol in the same repertoire.

The Unicode Standard distinguishes simple circled forms with explicit compatibility decompositions from more elaborate negative, double-circled and other forms treated as atomic symbols. As a result, normalizing one enclosed symbol can yield ordinary letters or digits while an almost-identical-looking enclosed symbol remains unchanged.

Do not infer identity by appearance: circled ①, negative circled ❶ and double circled ⓵ are distinct characters with different code points and normalization properties.

Unicode blocks and enclosed-number families

The primary Enclosed Alphanumerics block spans U+2460..U+24FF. It includes circled digits and numbers, parenthesized numbers and letters, digits with full stops, circled Latin capital and lowercase letters, and selected negative/double-circled forms. Other related characters appear in the Dingbats block, Enclosed Alphanumeric Supplement (U+1F100..U+1F1FF), and Enclosed CJK Letters and Months (U+3200..U+32FF).

Those blocks were designed around historical repertoires and application needs. They do not provide all possible combinations of a character with a frame; the numeric coverage is uneven. For example, ①..⑳ represent circled numbers 1–20, while a continuation of higher circled values, including ㉑, appears in the Enclosed CJK Letters and Months block. A developer should not assume that incrementing a code point indefinitely encodes the next number.

In particular, a circled numeral may have a defined compatibility decomposition representing multiple digits. ⑩ is a single code point but its NFKC decomposition is the two-character string "10". This changes not just shape but also string length and potentially search behavior.

The table shows that apparent enclosure similarity does not predict a decomposition. Unicode Chapter 22 explains that a single digit or letter in a simple circle frequently has a compatibility mapping tagged <circle>, whereas several elaborated negative or double-circled symbols are deliberately atomic. U+24EA is the precomposed circled zero, not a private-use glyph. U+20DD COMBINING ENCLOSING CIRCLE is a different mechanism entirely.

Combining enclosing marks are not precomposed circled symbols

You can store U+0041 U+20DD (A followed by COMBINING ENCLOSING CIRCLE), but Unicode does not declare this sequence canonically equivalent to U+24B6 Ⓐ. Full mark-to-base placement is also not universally supported, and no general standardized mechanism says that one enclosing mark should wrap an arbitrarily long preceding string. Avoid claiming a single combining mark can encode circled words of unlimited length.

Compatibility decompositions versus atomic signs

Canonical normalization (NFC/NFD) generally preserves circled alphanumeric code points. Compatibility normalization (NFKC/NFKD) expands forms that carry a compatibility mapping into their underlying letters, digits or punctuation. The expansion can increase length, remove the enclosure and make the text compare equal to an ordinary string.

console.log("\u2460".normalize("NFKC")); // "1"
console.log("\u2469".normalize("NFKC")); // "10"
console.log("\u2474".normalize("NFKC")); // "(1)"
console.log("\u24B6".normalize("NFKC")); // "A"
console.log("\u3251".normalize("NFKC")); // "21"

// Not every circled-looking symbol has a decomposition.
console.log("\u24F5".normalize("NFKC") === "\u24F5");
// true: double-circled one remains atomic
console.log("\u{1F150}".normalize("NFKC") === "\u{1F150}");
// true: negative circled capital A

This distinction is important for archival text, transcription, search and comparison. Two visually related enclosed symbols can normalize differently. A site that promises “remove all circles with NFKC” will be wrong for atomic negative/double-circled forms. Conversely, a site that needs to preserve an ordered list's exact glyph should avoid overwriting the original text with NFKC output.

Compatibility equivalence is deliberately weaker than canonical equivalence. A circled number can have a separate textual purpose even if it decomposes to ordinary digits; an interface should not assume NFKC always preserves the user's intended meaning or list structure.

Creating safe circled-letter and number mappings

Some subsets are regular enough for a careful arithmetic converter. Circled Latin uppercase A–Z occupy U+24B6..U+24CF and lowercase a–z occupy U+24D0..U+24E9. Circled numbers one through twenty run from U+2460 to U+2473, with zero handled separately by U+24EA. Those ranges should be used only within their exact documented bounds.

function circledLatin(text) {
  return [...text].map(ch => {
    const cp = ch.codePointAt(0);
    if (cp >= 0x41 && cp <= 0x5A)
      return String.fromCodePoint(0x24B6 + cp - 0x41);
    if (cp >= 0x61 && cp <= 0x7A)
      return String.fromCodePoint(0x24D0 + cp - 0x61);
    return ch;
  }).join("");
}
function circledNumber(n) {
  if (!Number.isInteger(n) || n < 0 || n > 20)
    return null;
  return String.fromCodePoint(
    n === 0 ? 0x24EA : 0x2460 + n - 1
  );
}
console.log(circledLatin("Abz")); // Ⓐⓑⓩ
console.log(circledNumber(10));    // ⑩
console.log(circledNumber(21));    // null: different block

Note that a converter for circled numbers 21–50 needs a separate verified range in Enclosed CJK Letters and Months; values beyond the supported repertoire may require drawing HTML/CSS, a font feature, or plain text—not a guessed Unicode scalar. The circled-Latin mapping also leaves non-Latin letters, accented letters and digits unchanged by design.

A Fancy Text generator can expose circled alphabet variants for copying, but it should not silently substitute an unrelated character when a requested circle form does not exist. For a product needing circles around arbitrary words, use real presentation markup instead of misrepresenting Unicode coverage.

Rendering, list semantics and accessibility

The same circled character can render with different ring size, stroke, baseline and font fallback. In a proportional layout, it does not guarantee a monospaced cell. East Asian legacy forms may have default fullwidth behavior, but actual glyph advance depends on font and shaping. Terminal and spreadsheet implementations can disagree about how many columns a symbol occupies.

When a document contains a genuine ordered list, semantic HTML such as <ol> with CSS counters is usually better than manually typing circled numeral characters into every item. It preserves list structure for assistive technology, supports arbitrary item counts and avoids exhausting the available Unicode circled-number repertoire. Circled code points are appropriate when a specific reference sign needs to survive as literal plain text.

Screen readers may announce the Unicode name of a circled or negative symbol, say its digit/letter, or produce less consistent speech. For important instructions, a nearby ordinary-language label is safer than relying on a decorative circle to be understood.

Searching, copying, validation and confusables

Exact equality distinguishes "1" from "①" unless an application explicitly applies compatibility normalization. As with mathematical letters, NFKC may make some circled symbols compare equal to plain text, but cannot be assumed to do so for every enclosed variant. A security-sensitive username policy should define whether such variants are accepted, normalized or flagged.

When text is copied through messaging apps, some platforms keep the literal symbols while others filter unsupported characters or display missing-glyph boxes. Always compare returned code points rather than relying only on appearance. Validate UTF-8 byte budgets separately from a visual item count: one circled character can use multiple bytes where an ASCII digit uses one.

Do not use the presence of an enclosing symbol as proof of a semantic status, such as verified identity, official certification or product rating. Unicode encodes the shape as text data; any meaning beyond that comes from the author and application context.
